# 独立レビュー

[English](independent-review.md) · [한국어](independent-review.ko.md) · **日本語**

通常のメッセージは従来どおり対応する作業会話に届きます。`send --mode review` は受信側の作業会話を起動せず、新しい CLI の文脈で読み取り専用レビューを一度実行します。関連する `result` は通常のメッセージとして戻るため、依頼側の会話ではターンが発生する場合があります。会話全体を要する作業より、小さな独立した質問に適しています。

## 受信アドレスごとの設定

提供者の CLI を別途インストールし、ChatGPT または Claude のサブスクリプションでログインしてください。CLI の自動インストール、ログイン変更、API キーへの代替はしません。Windows では最新のネイティブ `.exe` を指定し、`.ps1`・`.cmd` は使えません。必要な引数のない旧版は失敗して停止します。サブスクリプションの利用制限は引き続き適用されます。

UTF-8 の `review.json` を作成し、パスとモデルを自分の環境に合わせてください。アカウントで利用可能なモデルを指定し、自動代替は行いません。

```json
{
  "cli": "C:/Tools/provider/cli.exe",
  "model": "YOUR-AVAILABLE-MODEL",
  "jobRoot": "C:/relay-review-jobs",
  "evidenceDirs": ["C:/review-evidence"],
  "deadlineMs": 180000
}
```

`jobRoot` はプロジェクトや上位の AGENTS.md・CLAUDE.md・.git の外に配置します。根拠フォルダーは8個までで、メールデータやレビュー記録とは分離してください。認証情報やホーム全体は指定しないでください。ユーザーレベルの必須指示は適用される場合があります。指定範囲は **レビュー担当への指示であり、OS が強制する読み取り許可リストではありません。** 秘密情報は提出せず、提供者の読み取り専用制御を維持してください。

```powershell
.\relay.cmd review-config --root C:\relay-data --as claude-demo --config-file review.json
# 通常と同じく、受信する会話内で実行:
.\relay.cmd start --root C:\relay-data --as claude-demo
.\relay.cmd send --root C:\relay-data --as codex-demo --mode review --task R1 --body-file question.txt --wake
```

逆方向には `codex-demo` に Codex の実行ファイルとモデルを別途設定します。更新後は実行中のヘルパーを停止し、それぞれの受信会話内で再登録してください。別のインストール先や稼働中の非公開ヘルパーは自動変更しません。

## 再レビュー・状態確認

```powershell
.\relay.cmd send --root C:\relay-data --as codex-demo --mode followup --previous <直前のレビュー依頼の完全ID> --task R1 --body-file followup.txt --wake
.\relay.cmd review-status --root C:\relay-data --as claude-demo
.\relay.cmd review-config --root C:\relay-data --as claude-demo --off
```

followup は同じペア・タスクの直前の **依頼** の完全 ID を使用します。回答の ID ではありません。結論・根拠・次の行動だけを、シリアライズ後6,000文字以内で渡し、省略の有無を明示します。セッション再開や会話全体の入力はしません。依頼は UTF-8 で64 KiB まで、結果の構造と大きさも検証します。

## 信頼性と費用

- 実行記録は依頼全体、データ位置、受信先、ID に結び付きます。中断・不確実な実行を自動で繰り返しません。所有プロセスが消えた実行は `review-status` で保留と表示します。PID の存在も進捗の証明ではありません。
- 保存済み結果は再起動後もモデルを呼ばずに返信を完了できます。返信保存の試行記録だけがあり正確な関連返信がなければ保留します。原文が保管先に移動しても既存返信と照合します。外部モデル処理の厳密な一度限りの実行は保証しません。
- 実行・認証・制限時間・出力エラーでは通常、停止理由を関連返信に保存します。クラッシュや保存・返信エラーは保留のままになる場合があります。状態と作業ログを確認し、自動再送や一括完了は避けてください。
- `replied` は関連返信の保存と原文の保管を示し、依頼側 AI の受信・行動は証明しません。通常の `accepted` も転送の接受のみです。レビュー待ちは `reviewPending` として通常配送の件数と分離します。
- アドレスごとにレビューを一つずつ実行し、通常配送は別に処理します。停止時は制限時間内の実行終了を待ち、未実行の依頼は残します。タイムアウト時は子プロセス群の終了を要求しますが終了完了は保証しません。無効化したレビューを作業会話へ代替配送しません。
- 通常配送はモデルを呼びません。任意のレビューは CLI のサブスクリプション枠を消費し、使用量と経過時間をローカルに保存します。API キーや別の提供者への環境設定は拒否します。この機能に別途 API 支払いは必要ありません。速度・利用枠・トークン削減の一定の効果は保証しません。キャッシュ有無の入力、出力、作業全体を比較してください。

作業フォルダーには依頼・ログ・結果・使用量が残ります。プロジェクト資料同様に保護し、不要になったら手動で削除してください。履歴の自動削除はありません。公開テストは分離した試験データを用います。アプリ・CLI の互換性と外部ユーザーの導入はまだ実験段階です。

アドレス全体の実行記録はデータフォルダーの `reviews/<アドレス>/execution.json` です。個別記録の保存前にクラッシュしても `review-status` の `execution` に表示します。子プロセスの終了を確認できなければ保持し、再起動後も次のレビューを停止します。通常配送は継続します。受信処理を停止した後、オーナーが作業とプロセスの終了を確認した場合のみ手動で解除してください。経過時間や親 PID の不在だけで削除しないでください。安全に保存された結果・返信は照合後に対応する実行記録を自動解除します。

公式説明: [Codex 非対話実行](https://learn.chatgpt.com/docs/non-interactive-mode)、[Claude CLI](https://code.claude.com/docs/en/cli-reference)。追加の API SDK は不要です。
