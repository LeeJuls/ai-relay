# Discord 요약 봇 사용 안내

현재는 **각 대화에서 요약 작성 → 운영 작업에서 본문 검토 → 오너 승인 → 각 봇 1건 게시** 방식입니다. Discord 멘션이나 Claude/Codex 대화 안의 특별한 명령으로 봇이 자동 호출되지는 않습니다. 모델을 서로 연결하거나 기존 대화를 resume하지 않습니다.

## 각 대화에 붙일 요청

Claude의 선택한 작업 대화:

```text
이 대화에서 직접 수행한 작업을 Discord 공유용으로 요약해줘.
완료 / 직접 검증 / 전달받은 결과(직접 검증 아님) / 미검증·막힘 / 다음 할 일을 구분해줘.
작성일과 상태를 확인한 시각을 적고, 모르는 시각은 추정하지 마.
비밀값·개인 경로·전체 대화·다른 프로젝트 정보·멘션은 제외해줘.
아직 봇을 실행하거나 게시하지 말고 내가 전달할 짧은 요약만 작성해줘.
```

Codex의 선택한 구현 작업 대화:

```text
현재 작업에서 직접 확인한 내용만 Discord 공유용으로 요약해줘.
완료 / 직접 검증(시험 범위와 제외 포함) / 미검증·막힘 / 다음 할 일과 작성 시각을 적어줘.
비밀값·개인 경로·전체 대화·다른 프로젝트 정보·멘션은 제외해줘.
모델 연결 성공과 단순 요약 게시를 구분하고, 아직 게시하지 마.
```

Claude 요약은 오너가 운영 대화로 전달합니다. 출처는 `user_forwarded`이며 직접 세션 인증으로 취급하지 않습니다. Codex 요약은 해당 작업의 `current_task_authored`입니다. 실제 Claude/Codex의 도구 실행 권한과 요약을 게시하는 봇의 권한은 별개입니다.

## 운영 작업의 준비·승인

- 운영자는 `prepareSummary` 라이브러리로 출처·시각·레이블을 포함한 최종 본문을 구성합니다. 실제 대화용 범용 prepare CLI는 아직 없습니다. 현재 준비는 운영자가 수행하는 명시적 작업입니다.
- 최종 본문은 1,800 UTF-16 단위 / 4,096 UTF-8 바이트 이하이어야 합니다. 초과·알려진 비밀/개인 경로/멘션 패턴은 치환·절단하지 않고 거부합니다. 사람의 검토도 필요합니다.
- 오너는 두 본문 전체와 각각의 raw UTF-8 SHA-256, 대상 봇·채널·각 1건을 확인합니다. 시각·출처·내용이 바뀌면 해시도 바뀌므로 다시 확인해야 합니다.
- `준영-claude`와 `준영-codex`의 선택은 ignored `.discord.summary.local.json`의 엄격한 binding으로 고정됩니다. 표시 이름만으로 인증하지 않습니다. 이 설정은 승인 자료와 분리되며 token 필드를 허용하지 않습니다.
- 승인 후에만 운영자가 15분 이내 유효한 `approved.json`을 만듭니다. 프로그램이 승인 자체를 생성하거나 증명하지 않습니다. token·권한·본문에 대한 별도 승인 범위를 지켜야 합니다.

## 실제 지원 명령

소스 checkout에서 Node 24.14.x를 사용합니다.

```powershell
# 오프라인 가짜 데이터 시험. 인증·실제 게시 없음.
node --test test/discord-summary-*.test.mjs

# 별도로 승인받은 경우의 일회성 실제 신원·권한 GET 점검
node tools/discord-summary/verify-bots.mjs --verify

# 오너가 최종 본문과 실제 게시를 승인한 미사용 시험에 한함
node tools/discord-summary/publish-approved.mjs --publish
```

`verify-bots`는 각 봇 4개 GET을 순차 수행합니다. `publish-approved`는 권한 사전점검을 포함해 정상 완료 시 GET 10개와 POST 2개를 사용하고, Claude 다음 Codex 순으로 각 1건 게시 후 종료합니다. Gateway·AI 호출·메시지 기록 조회·자동 응답·재시도는 없습니다. token은 기존 `.env.discord.local`과 별도 `.env.discord.codex.local`에서 프로그램만 읽습니다. 저장은 평문이며 Git 제외가 암호화를 뜻하지 않습니다.

## 이번 시험은 이미 종료됨

현재 로컬 시험은 `finished`, accepted 2건이며 provider quota를 각각 1개 소비했습니다. 재실행은 허용되지 않습니다. 오래된 승인 artifact는 만료 검사에서도 거부됩니다. 같은 시험을 다시 호출해 확인할 필요가 없습니다.

새 요약을 일상적으로 반복 게시하는 준비/승인/회차 관리 CLI는 **아직 미구현**입니다. ledger 삭제, 새 root·trial ID·revision·시각으로 바꿔 이번 중복 방지를 우회하면 안 됩니다. 다음 실제 게시에는 별도의 새 시험 정책과 오너 승인이 먼저 필요합니다. 지금은 요약을 작성해 운영 대화에 전달하고 게시 전 상태로 보관할 수 있습니다.

불확실한 POST는 `held`로 보존합니다. 자동 재전송하지 말고 실제 상태를 사람이 확인해야 합니다. Bot runtime은 상주하지 않으므로 Discord에서 멘션한다고 작업 세션이 깨거나 답하지 않습니다. `/relay-test`는 과거 별도 제한 질문 demo이며 이 요약 공유 기능을 호출하는 명령이 아닙니다.
